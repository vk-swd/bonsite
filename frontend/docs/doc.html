Basic overview

This project demonstrates a simple Node.js + GraphQL + Kafka + MS SQL backend service architecture. I have chosen to build a simple bank statement generator service that would replicate a hypothetical operation flow of services involved in transaction data collection and its presentation. The diagram on Pic.1 demonstrates basics of what the system is built to do: Client1 posts a transaction with Client2 into the system and that transaction becomes available as part of a bank statement.

A more detailed overview

The Pic.2 describes the interaction between frontend and backend components of the system.

At a lower level the server is composed of the following elements:

  1. Kafka server – stores a log of transactions posted by clients

  2. Sql server – a database that stores transactions in a structured manner better suited suitable for querying and analytics

  3. Message sink – a Node.js application that continuously polls messages from Kafka server and forwards them to Sql.

  4. GraphQL server – accepts the following requests:

    1. Post transaction – send a request to store a { from, to, date, amount } data structure to Kafka

    2. Get a statement for a user


To demonstrate how system works I made a web page with UI elements that communicate with the GraphQL server. The page helps do the following:

  1. Define transaction parameters and post it – convenient to trace the state change

  2. Generate a number of transaction between random users – convenient to quickly produce lots of transactions and see how system behaves with more data.

  3. Get a transaction list for a selected user and date range – provides a paginated output that can be scrolled through chronologically.


Technical notes:

  1. The implementation of server has another two components that I omitted before for simplicity:

    1. Transaction generator – a Node.js application that does the following:

      1. Accepts requests from GraphQL server

      2. Generates transactions based on generation parameters

      3. Generates transactions from individual transaction post requests

      4. Sends generated data to Kafka

      5. Provides generation progress reports

    2. Statement generator – another Node.js application that:

      1. Accepts statement requests from GraphQL server

      2. Responds with requested bank statement chunks

      3. Also responds with full statement files (not implemented in UI yet)

      4. Provides user list for the user selector in Web page

      5. Reports database stats (not embedded in UI yet)

  2. All Node.js apps have a http server to report stats to Prometheus

  3. There is also a Graphana dashboard linking to Prometheus

  4. Everything is deployed using docker compose.

  5. Databases are deployed in tmpfs to not to damage my SSD as the project is hosted on my home server.

    1. For those reasons data is rotated in Kafka by configuring retention bytes to 500 MB per topic.

    2. Also data is rotated in SQL Server by deleting oldest rows to maintain the database file size of 2G and setting a SIMPLE recovery mode to avoid a growing transaction log. Transaction log is also flushed after every transaction.

  6. Web pages are served and requests are proxied by Nginx, with a Node.js application handling authorisation.

  7. Frontend and backend bundles are hosted from different machines in my house and backend machine will be off sometimes. I will try to keep everything up as much as possible, but if it is not, backend requests will get 502 error.
